## A. OpenCode 生态

### A.1 OpenCode 是 MIT 开源项目 📄
- 仓库：`https://github.com/sst/opencode`（anomalyco/opencode）
- 17万+ star，TypeScript 主体
- 包名：`opencode-ai` (npm)
- 最新版：v1.16.2 (2026-06-05)
- License：MIT

### A.2 OpenCode 服务端化架构 📄
- `opencode serve [--port 4096] [--hostname 127.0.0.1]` 启动 headless HTTP server
- 默认端口：**4096**
- 默认 hostname：**127.0.0.1**（localhost only）
- 鉴权：HTTP Basic Auth，`OPENCODE_SERVER_PASSWORD` 环境变量
- 默认 username：`opencode`，可用 `OPENCODE_SERVER_USERNAME` 覆盖
- OpenAPI 3.1 spec 在 `http://<host>:<port>/doc`
- 核心端点：
  - `GET /global/health` — 健康检查
  - `GET /global/event` — 实时事件 (SSE)
  - `GET /project` — 项目信息
  - `POST /session` — 创建 session
  - `POST /session/:id/message` — 发送消息
  - `POST /tui/append-prompt` — 追加 prompt

### A.3 OpenCode 有完整 Node SDK 📄
- 包名：`@opencode-ai/sdk` (npm)
- Vercel AI SDK 集成：`ai-sdk-provider-opencode-sdk` v3.x（v6 支持）
- 配置示例：
  ```ts
  const opencode = createOpencode({
    hostname: "127.0.0.1",
    port: 4096,
    autoStartServer: true,
    serverTimeout: 10000,
    defaultSettings: { agent: "build", title: "My Session" },
  });
  ```

### A.4 OpenCode 自定义 provider 配置 📄
- 配置位置：`~/.config/opencode/opencode.jsonc` 或项目级 `opencode.json(c)`
- 自定义 OpenAI 兼容 provider 模板：
  ```jsonc
  {
    "provider": {
      "myprovider": {
        "npm": "@ai-sdk/openai-compatible",
        "name": "My Provider",
        "options": {
          "baseURL": "https://api.example.com/v1",
          "apiKey": "sk-xxx"
        },
        "models": {
          "my-model": { "name": "My Model" }
        }
      }
    }
  }
  ```
- 用 `npm: "@ai-sdk/openai-compatible"`（`/v1/chat/completions`）或 `"@ai-sdk/openai"`（`/v1/responses`）

### A.5 OpenCode 内置 provider（"opencode"）💬
- 来源：opncd 对话 match 56 (1900 字符的 auth 文件 dump)
- OpenCode 桌面版的 auth 文件包含 `volcengine-coding`, `opencode-go` 等账号
- 免费模型走 `opencode` provider（baseURL 是 OpenCode 自己的代理）
- 用户可以从外部调用这个 endpoint（OpenAI 兼容）

### A.6 MiMo Code 是 OpenCode 的 fork 💬
- 来源：opncd 对话 match 7（Koko 官方文档摘要）
- **MiMo Code 是小米 MiMo 团队基于 OpenCode 二次开发的终端 AI 编程 Agent，MIT 协议开源**
- 保留 OpenCode 的核心能力（多 Provider、TUI、LSP、MCP、插件）
- 新增：持久化记忆（基于 SQL）、增强 UI 等
- 配置差异：
  | 维度 | OpenCode | MiMo Code |
  |---|---|---|
  | 配置目录 | `~/.config/opencode/` | `~/.config/mimocode/` |
  | 主配置 | `opencode.jsonc` | `mimocode.jsonc` |
  | 项目配置 | `opencode.json(c)` | `mimocode.json(c)` |
  | 项目目录 | `.opencode/` | `.mimocode/` |
  | 环境变量前缀 | `OPENCODE_*` | `MIMOCODE_*` |
- 安装位置：`D:\nodejs\node-v20.11.0-win-x64\node_modules\@mimo-ai\cli\bin\mimo`
- AVX2 baseline 二进制：`@mimo-ai/mimocode-windows-x64-baseline`

### A.7 opencode run --attach 模式 📄
- 启动 headless server 在一个终端：`opencode serve`
- 在另一个终端运行 attach：`opencode run --attach http://localhost:4096 "任务"`
- **关键设计意图**：避免 MCP server 冷启动开销，attach 到已运行的 server
- 这正是 openchat 想要的模式！

## B. OpenClaw 生态（独立于 OpenCode）

### B.1 OpenClaw 是独立 agent runtime 📄💬
- 来源：opncd 对话 match 88 + npm 官方文档
- 官方网站：`https://openclaw.ai/`、`https://docs.openclaw.ai/`
- 包名：`openclaw` (npm)，独立 CLI
- 最新版本要求：>= 2026.3.22
- 维护方：腾讯（Tencent）+ 社区
- 渠道：Slack、Discord、Signal、WhatsApp、Telegram、WebChat、**微信**

### B.2 OpenClaw 微信插件（已存在）📄
- 包名：`@tencent-weixin/openclaw-weixin` (npm)
- 维护方：Tencent 官方
- 最新版本：2.4.3
- 安装：`npx -y @tencent-weixin/openclaw-weixin-cli install`
- 或：`openclaw plugins install "@tencent-weixin/openclaw-weixin"`
- 启用：`openclaw config set plugins.entries.openclaw-weixin.enabled true`
- 登录：`openclaw channels login --channel openclaw-weixin`

### B.3 OpenClaw 插件 SDK 详细规范 📄
- SDK 子路径：`openclaw/plugin-sdk/*`
- Channel 插件通过 `defineChannelPluginEntry` / `createChatChannelPlugin` 实现
- 插件对象结构（节选）：
  ```ts
  export const acmeChatPlugin = createChatChannelPlugin<ResolvedAccount>({
    base: createChannelPluginBase({
      id: "acme-chat",
      setup: { resolveAccount, inspectAccount },
    }),
    security: { dm: { /* 鉴权 */ } },
    pairing: { text: { /* 配对流程 */ } },
    outbound: { /* 出站消息 */ },
  });
  ```
- Channel 插件入口：`package.json` 的 `channel` 字段标识

### B.4 openchat 当前实现的微信协议与 openclaw 微信插件 **完全同源** 🔍
- 关键证据：`openchat/markdown-filter.js` 文件头注释

- 这意味着 openchat 的 wechat API 模块本身就是从 openclaw 微信插件移植过来的
- 端点清单（openchat 当前实现）：

  | `getUpdates` | ✅ `ilink/bot/getupdates` | ✅ `getupdates` |
  | `sendMessage` | ✅ `ilink/bot/sendmessage` | ✅ `sendmessage` |
  | `getUploadUrl` | ✅ `ilink/bot/getuploadurl` | ✅ `getuploadurl` |
  | `getConfig` | ✅ `ilink/bot/getconfig` | ✅ `getconfig` |
  | `sendTyping` | ✅ `ilink/bot/sendtyping` | ✅ `sendtyping` |
  | `notifyStart` | ✅ `ilink/bot/msg/notifystart` | ❌ 旧版没有 |
  | `notifyStop` | ✅ `ilink/bot/msg/notifystop` | ❌ 旧版没有 |

## C. openchat 当前实现的关键约束 🔍

### C.1 强依赖 opencode 桌面版
- `opencode-client.js:22-24` 注释：
  ```js
  /**
   * opencode-client.js — OpenCode HTTP API 客户端
   * 仅从环境变量获取桌面版密码（OpenCode 内置终端自动注入）
   * 无其他密码来源，保持极简
   */
  ```
- 鉴权完全靠 `OPENCODE_SERVER_PASSWORD` 环境变量
- README 警告："openchat 只能在 OpenCode 内置终端运行"

### C.2 模型管理强依赖桌面版 API
- `src/models.js` 通过 `GET /api/model` 拉取模型列表
- `GET /session` 创建 session
- 整个 agent 调用链路：`POST /session/:id/message`

### C.3 暖机机制强依赖桌面版
- `bridge.js:194-249` 启动暖机循环
- 必须有桌面版在 `127.0.0.1:<random_port>` 监听

### C.4 鉴权机制特殊
- 不是 OAuth，是 HTTP Basic Auth
- username 默认 `opencode`，password 来自环境变量
- 桌面版启动时把密码注入到内置终端子进程 → openchat 才能拿到

## D. 三个设想的成立条件

### D.1 设想 1（独立化）成立条件
✅ 满足：
- `opencode serve` 是 headless server，不需要桌面版
- `@opencode-ai/sdk` 是官方 Node SDK
- openchat 的所有调用都基于 HTTP API，可无缝替换
- 密码可以通过环境变量手动设置（不需要桌面版注入）

### D.2 设想 2（CLI 重构）成立条件
✅ 满足：
- `opencode serve` 已经验证可独立运行（opncd 对话）
- `opencode run --attach` 模式专为外部 attach 设计
- openchat 的协议栈与 opencode 服务端 API 完全兼容
- mimocode 已经证明这条路径可行（小米也用同样的方式）

### D.3 设想 3（openclaw 插件）成立条件
✅ 满足：
- OpenClaw 是真实存在的独立 runtime（不只是设想）
- 微信插件 SDK 已完整定义
- openchat 的微信协议 100% 与 openclaw-weixin 同源
- 只需把 "调用 opencode HTTP" 改成 "调用 openclaw gateway"
- 包名可以发布为 `openchat-wechat` 或类似（与现有 `openclaw-weixin` 并存）

## F. 🚨 关键负面发现：opencode 1.15.x 鉴权 Bug（2026-06 已知）

**日期**：2026-06-12（本次重构发现）
**来源**：
- GitHub issue #31254 (2026-06-07 提交，最新)
- GitHub issue #29847 (2026-05-29 提交)
- GitHub issue #9706 (2026-01-20，已修)

### F.1 Bug 现象

```bash
$ OPENCODE_SERVER_PASSWORD=xxx opencode serve --port 4096
$ curl -u opencode:xxx http://127.0.0.1:4096/global/health
HTTP 401, www-authenticate: Basic realm="Secure Area"
```

### F.2 根因

`packages/opencode/src/server/server.ts` 的 server middleware 启用 Basic Auth，但客户端不主动带 Authorization header。

### F.3 opncd 对话里的"成功"是怎么来的？

opncd 对话 match 76 说"完美。免费通道完全可用"——这次验证（2026-06-12）确认了 **那次的成功来自 mimocode，不是 opencode 1.15.x**。mimocode 是基于更早的 opencode 版本，没有这个 bug。
