# OpenChat 重构方案 — 详细技术方案

## 0. 问题陈述

当前 openchat v1.5.0 存在以下硬约束：

| 约束 | 现状 | 痛点 |
|---|---|---|
| 必须 opencode 桌面版 | README 强警告"只能在 OpenCode 内置终端运行" | 桌面版启动慢、资源占用大、必须 GUI |
| 鉴权机制特殊 | 桌面版把 `OPENCODE_SERVER_PASSWORD` 注入到内置终端子进程 | 无法脱离桌面版启动 |
| 只能做 1:1 桥 | 是"opencode 的伴侣"而非独立产品 | 无法独立分发、无法对接其他 agent runtime |
| 与 OpenClaw 微信插件代码同源但不同步 | openchat 的 markdown-filter.js 是从 openclaw-weixin 移植的 | 升级时容易漂移 |

**核心问题**：openchat 把自己定位成"opencode 桌面版的依赖项"，限制了它的能力边界。

---

## 1. 三个设想的详细展开

### 设想 1 — openchat 完全独立化（最小代价）

**核心思想**：openchat 本质是 HTTP 客户端，跟 OpenCode 服务端通讯。只要能拿到 `OPENCODE_SERVER_PASSWORD`，就能完全脱离桌面版。

**实现路径**：
```
┌─────────────────────────────────┐
│  openchat (改造后)              │
│  ┌──────────────────────┐       │
│  │  wechat 层（保留）    │       │
│  │  - 长轮询收消息        │       │
│  │  - 发消息、分段        │       │
│  └──────────────────────┘       │
│  ┌──────────────────────┐       │
│  │  bridge 层（保留）    │       │
│  │  - 消息批次合并        │       │
│  │  - / 命令系统          │       │
│  └──────────────────────┘       │
│  ┌──────────────────────┐       │
│  │  agent 层（替换）     │       │
│  │  旧：HTTP 直调桌面版   │       │
│  │  新：@opencode-ai/sdk │       │
│  └──────────────────────┘       │
└─────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────┐
│  opencode serve (headless)      │
│  port=4096                      │
│  OPENCODE_SERVER_PASSWORD=xxx   │
│  （由 openchat 启动并管理）       │
└─────────────────────────────────┘
```

**关键改动**（diff 级别）：
- `opencode-client.js`：用 `@opencode-ai/sdk` 替换裸 `fetch`
- `bridge.js`：移除"必须在 OpenCode 内置终端运行"的检查
- `config.js`：新增 `OPENCODE_SERVER_AUTO_START` 配置项（默认 true）
- 新增 `server-bootstrap.js`：负责启动 `opencode serve` 子进程、生成密码、注入环境变量

**依赖变化**：
- 旧依赖：opencode 桌面版 GUI
- 新依赖：`opencode-ai` (CLI, npm) + `@opencode-ai/sdk` (SDK, npm)

**最小 PoC 文件**：
- `设想1-openchat独立化/lib/openchat-sdk.js`
- `设想1-openchat独立化/lib/openchat-wechat.js`
- `设想1-openchat独立化/examples/standalone-demo.js`

---

### 设想 2 — 基于 opencode CLI 重构（完整形态）

**核心思想**：opencode CLI 本身就是 headless 可调用的（`serve + run --attach`）。openchat 可以包装这套 CLI，把"启动 opencode + 启动微信桥"做成一条命令。

**实现路径**：
```
$ openchat
  → 启动 opencode serve (后台)
  → 启动 wechat monitor (前台)
  → bridge 两者（消息路由）
  → Ctrl+C 时优雅关闭
```

**架构图**：
```
┌──────────────────────────────────────────┐
│  openchat CLI (新)                       │
│  $ openchat [--port 4096] [--agent build]│
│                                          │
│  1. 检查 opencode 是否已运行              │
│  2. 没有则启动 opencode serve             │
│  3. 检查微信 token                        │
│  4. 没有则引导扫码登录                    │
│  5. 启动微信长轮询                        │
│  6. 收到消息 → SDK 调用 opencode agent   │
│  7. 收到回复 → 发送到微信                 │
│  8. Ctrl+C → 优雅关闭所有子进程           │
└──────────────────────────────────────────┘
     │                              │
     ▼                              ▼
┌─────────────────┐         ┌─────────────────┐
│ opencode serve  │         │ wechat server   │
│ 127.0.0.1:4096  │         │ ilinkai.weixin  │
│ (headless)      │         │ (long-poll)     │
└─────────────────┘         └─────────────────┘
```

**关键改动**：
- 新增 `bin/openchat` / `bin/openchat.cmd` 启动器
- 新增 `src/server-bootstrap.js`：启动 opencode 子进程并管理
- `package.json`：增加 `opencode-ai` 作为 peer dependency
- 移除 README 中的"内置终端"硬约束

**用户体验对比**：

| 操作 | v1.5.0（当前） | v2.0.0（设想 2） |
|---|---|---|
| 启动 opencode | 必须打开桌面版 GUI | 自动后台启动 |
| 启动 openchat | 必须在 opencode 内置终端 | 任何终端都行 |
| 配置密码 | 由 opencode 桌面版自动注入 | 启动器生成 + 保存 |
| 跨平台 | 仅 Windows | Windows/macOS/Linux |
| 资源占用 | 大（GUI） | 小（headless） |

### 设想 3 — 改造成 OpenClaw 插件（终极形态）

**核心思想**：openchat 的 wechat 协议 100% 来自 openclaw-weixin。直接把它做成 openclaw 的插件，让 openclaw 来管理 agent runtime（可以是 opencode、mimocode 或任何其他 backend）。

**实现路径**：
```
$ openclaw plugins install openchat-wechat
$ openclaw config set plugins.entries.openchat-wechat.enabled true
$ openclaw channels login --channel openchat-wechat
$ openclaw gateway restart
```

**架构图**：
```
┌──────────────────────────────────────────┐
│  OpenClaw Gateway (agent runtime)        │
│  - 注册 channels                         │
│  - 注册 agents (build, plan, explore...) │
│  - 消息路由                              │
│  - 模型调用                              │
└──────────────────────────────────────────┘
     │
     ├── plugins.entries.openchat-wechat (新)
     │     │
     │     ▼
     │   ┌────────────────────────────┐
     │   │ openchat-wechat plugin     │
     │   │  (改造自 openchat 项目)     │
     │   │                            │
     │   │ - QR 登录                  │
     │   │ - 长轮询 getupdates        │
     │   │ - sendmessage/sendtyping   │
     │   │ - CDN 图片处理             │
     │   │ - markdown filter          │
     │   └────────────────────────────┘
     │
     ├── plugins.entries.openclaw-weixin (已有)
     │     └─ 另一套微信实现（未来可统一）
     │
     └── agents (build, plan, ...)
```

**关键改动**：
- 新建独立项目 `openchat-wechat` 作为 OpenClaw 插件
- 保留 openchat 的所有 wechat 协议代码
- 移除 openchat 中的 opencode-client.js（由 openclaw 接管 agent 调用）
- 移除 openchat 中的 opencode-server-bootstrap.js（由 openclaw 管理 agent）
- 保留：wechat-api.js, wechat-auth.js, cdn.js, markdown-filter.js, session-store.js

**插件 manifest**：
```jsonc
// package.json (插件)
{
  "name": "openchat-wechat",
  "version": "1.0.0",
  "openclaw": {
    "channel": {
      "id": "openchat-wechat",
      "displayName": "WeChat (via OpenChat)",
      "entry": "./src/channel.js",
      "configSchema": "./config-schema.json"
    }
  }
}
```

**与 openclaw-weixin 关系**：
- `openclaw-weixin`：腾讯官方微信插件（轻量、纯官方 iLink 协议）
- `openchat-wechat`：社区维护（继承 openchat 的丰富特性：流式 Markdown、坏模型缓存、暖机、typing 提示）
- 两者并存，用户可选用

## 2. 实施路线图

### Phase 1 — 设想 1 PoC（1 周）
- 创建 `设想1-openchat独立化/`
- 编写不依赖桌面版的最小 SDK 包装
- 验证：能连接 `opencode serve`，能完成基本消息收发
- **不做**：流式输出、图片、暖机、模型探测

### Phase 2 — 设想 2 完整形态（2 周）
- 创建 `设想2-opencode集成/`
- 实现 `openchat` 启动器
- 实现 `server-bootstrap.js`
- 把原 openchat 的 `bridge.js` 改造为 attach 模式
- **做**：完整的微信 + opencode 桥，去掉桌面版依赖

### Phase 3 — 设想 3 插件化（2 周）
- 创建 `设想3-openclaw插件/`
- 编写 `openchat-wechat` 插件骨架
- 编写 channel.js 实现 ChannelPlugin 接口
- 复用 wechat-api.js / wechat-auth.js / cdn.js
- **目标**：发布到 npm，作为 `openclaw plugins install openchat-wechat` 可安装

### Phase 4 — 合并与发布（1 周）
- 三个设想的最终合并方案
- 文档、测试、CI
- 发布到 npm + 文档站

## 3. 关键设计决策

### 3.1 进程模型

| 设想 | 进程模型 |
|---|---|
| 设想 1 | 单进程：openchat 自启 opencode serve 作为子进程 |
| 设想 2 | 单进程：openchat 启动器包揽一切 |
| 设想 3 | 多进程：openclaw gateway 是主进程，openchat-wechat 是插件 |

### 3.2 鉴权

| 设想 | 鉴权方式 |
|---|---|
| 设想 1/2 | openchat 启动时生成随机密码，注入到 opencode serve 子进程 |
| 设想 3 | 由 openclaw gateway 统一管理，openchat-wechat 只通过 SDK 调用 |

### 3.3 协议兼容

| 设想 | 微信协议 |
|---|---|
| 全部 | iLink 官方协议（`ilinkai.weixin.qq.com`） |

### 3.4 opencode 版本兼容

| 设想 | opencode 版本 |
|---|---|
| 设想 1/2 | 锁定 `opencode-ai@^1.16.0` |
| 设想 3 | 由 openclaw 决定（openclaw 可能集成 opencode 作为 backend） |

---

## 4. 风险与回退方案

| 风险 | 回退方案 |
|---|---|
| `@opencode-ai/sdk` 还没稳定 | 暂时保留裸 `fetch` 调用作为备选 |
| `openclaw plugin-sdk` 接口变化 | 跟随 OpenClaw release，CI 锁版本 |
| opencode serve 启动失败 | 提示用户手动启动 `opencode serve` 后重试 |
| 微信协议封禁 | 不可控，保留二维码登录作为兜底 |
| openchat 用户群习惯了桌面版 | 在 README 明确"现在不需要桌面版"，提供迁移指南 |

---

## 5. 立即可做的

按优先级：

1. ✅ 验证 `opencode serve` 在本机能跑通（已经验证：opncd 对话）
2. ✅ 验证 `@opencode-ai/sdk` 可用（npm 包已存在 v1.16.x）
3. ⏳ 编写设想 1 的最小 PoC
4. ⏳ 编写设想 3 的插件骨架

---

## 6. 不做的事（明确边界）

- 不改 opencode CLI 本体
- 不改 OpenClaw 核心
- 不实现完整的工具调用 / MCP（保持 openchat 当前的纯聊天模式）
- 不支持群聊（openchat 当前不支持）

---

## 7. 与 openclaw-weixin 的关系

**重要澄清**：设想的终极形态不是替代 openclaw-weixin，而是与之**互补共存**：

| 插件 | 特点 | 适合用户 |
|---|---|---|
| `@tencent-weixin/openclaw-weixin` | 官方、轻量、稳定 | 生产环境、稳定优先 |
| `openchat-wechat` | 社区、特性丰富 | 尝鲜、喜欢流式输出、坏模型缓存等 |

openclaw 允许装多个 channel 插件，所以两者可以并存。
